## 场景与交互

场景是程序化虚拟模型，没有声称精确复刻公园建筑或改变真实相机画面。影子是模拟几何。没有实现对玩家裸手的识别；手机使用触屏，Quest使用控制器射线选择。

正常剧情在手势阶段、恢复演出、碎片领取和终章没有按钮直接跳过关卡。开场仍有“様子を見る”可提前进入冻结，“影を動かす”启动拖动，完成各阶段后才显示继续按钮。回看保留碎片，不重复领奖；回看完成的演出不自动推进。四季恢复与终章汇聚计时在丢卡／页面后台时暂停，重新显示后继续。拖影子与花瓣等操作松手后可重新开始，已计入的进度保留。

## 小H

沿用原始纯白和Time Traveler两张透明正面素材：2.5D细分网格变形＋3D位置，含Idle／Fly／Wave／Point／Celebrate与1.8秒两形态渐变特效。PNG、参考图、五张Marker及vendor文件未修改。

Point在舞台局部指向事件区域／碎片；Fly是在虚拟舞台内移动。不是完整多视角角色、骨骼动画、GPS导航或现实避障。开场变身和结束变回原形时继续按钮等待过渡结束。图片加载失败时仍保留旧程序化3D角色回退。两种造型可在character.html并列查看。

## 手机坐游运行

1. 将部署包解压，上传webar文件夹内全部项目内容到GitHub仓库根目录；应直接看到index.html、js、assets、vendor、package.json、vercel.json。
2. Vercel导入仓库：Framework Preset选Other、Build Command留空、Output Directory为`.`。如仓库内保留webar子文件夹，将Root Directory设为webar。
3. 使用部署后的HTTPS网址，打开print.html按100%倍率打印原来的5张卡片，无需重编targets.mind。
4. 手机首页选择「座って巡る」→「スマートフォン」，允许摄像头。按提示扫描日時計→春→夏→秋→冬→同一张日時計。
5. 手势在卡片上方的虚拟场景完成，保持卡片全貌在镜头中；丢卡后重新对准。若说明面板挡住模型，调整手机／卡片取景位置。
6. 最后点击「最初の画面へ」。回游入口仍是“準備中”，本版本未开发GPS／回游。

整套静态项目不需要数据库、服务器后端、npm安装或构建。学校Mac或Windows本地只需Python运行静态服务：

```sh
python3 -m http.server 5173
# Windows也可使用：py -m http.server 5173
```

电脑无摄像头预览：`http://localhost:5173/?preview=1`。扫描步骤在预览模式中提供模拟识别按钮；四季和日晷仍通过鼠标手势交互。开发入口为`?preview=1&debug=1`，可跳到指定地点／终章或查看小H动作；开发入口不会在普通网址中开放。

手机摄像头使用HTTPS；本地Python主要用于电脑预览。不要双击HTML直接打开。

本版本基于安全基线 v0.1.5（提交 `62badee40bbe98c83eca5feae6b899bbf2ff3d11`），只开发手机／无摄像头预览中的日時計开场模块。安全基线目录和原ZIP未修改。

## 本阶段写入的功能

- 新增 `js/sundial.js`：程序化立体日晷（底座、表盘、立体三角晷针、32个刻度）、时间环、影子末端光点。
- 使用屏幕指针射线与Marker局部平面求交，让手机手指／预览鼠标操作对应AR日晷。影子是模拟几何效果，不是实际光照计算。
- 顺时针拖影子：沿圆弧逐步推进，经过的刻度亮起；松手保留本次进度，可重新抓住末端继续。逆向拖动会减少进度，拖过中心或突跳不会直接通过。
- 拖到约129.6°后进入卡住阶段：影子轻微回弹，四道光纹和四个空槽依次显现。此时碎片仍为0/4。
- 手机／预览在拖动阶段没有“下一步”通关按钮；完成拖动后才显示继续旅行按钮。返回按钮保留旧版剧情回看逻辑，不会重复获得碎片。
- 卡片丢失、页面后台、取消触摸和场景切换时停止当前拖拽；卡片重新出现后可继续当前进度。
- 简化拖动阶段的底部说明面板，留出更多操作空间。

## 本阶段边界

- 小H保留原有两种程序化3D形态和简易切换；没有制作新版美术、飞行／指向或完整变身演出。
- 春、夏、秋、冬和返回日時計的终章仍为v0.1.5旧版流程。本阶段没有制作四季手势或终章完整转一圈。
- Quest 3保留旧版日時計舞台及按钮流程，不进入新增触屏拖动阶段；本阶段没有移植新的Quest手柄玩法。
- 开场仍由“様子を見る”按钮从运行切入冻结，不是自动8秒电影。小H仍按旧版在首页／教程提前出现。
- 四个空槽目前是几何线框，没有四季图纹、嵌槽收集动画或小H巡查空槽。
- 圆形原插画作为底部参考仍保留，立体日晷叠加其上。移动手机可观察Marker局部空间中的高度；没有真实桌面遮挡或环境网格。
- Debug开发入口保持原有可模拟行为；正常流程的拖动关卡不能用普通下一步按钮跳过。

2. 手机HTTPS实机：权限拒绝与重试、五张44mm打印卡、光照与倾斜、卡片丢失恢复、刷新与退出。
3. Quest实机：透视会话、左右手柄、相机许可、实际卡片识别、AR退出和重新进入。
4. 完成以上后再加入GPS、导航与现场目标识别，不复制游戏逻辑。

运行逻辑测试：`npm test`（无需npm install）。
